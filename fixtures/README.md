# Wire fixtures

Golden crypto vectors and session message samples for the Android client,
generated by compiling iTerm2 v3.7.7's own Swift sources. Files the generator
writes are never hand-edited: change the generator and regenerate them.

## Harness

`harness/` is a Swift package with two targets:

- `CompanionProtocol`: the public CompanionCore protocol files.
- `WireFixtures` (executable `wire-fixtures`): the generator, compiled in one
  module with `CompanionMessages.swift` and the rest of the iOS app's shared
  sources, because the message enums are `internal`.

`harness/upstream-files.txt` lists every upstream file and its target. The
copies under `harness/Sources/*/Upstream/` are not committed.

## Regenerate

Needs a Swift 6 toolchain (macOS, or Linux with the `swift:6.2-noble` image)
and network access to gitlab.com and github.com.

```sh
cd fixtures/harness
./sync-upstream.sh            # sparse-checks out v3.7.7 and copies the listed files
swift build
swift run wire-fixtures <out-dir>
```

Off Darwin, `sync-upstream.sh` rewrites `import CryptoKit` to `import Crypto`
(swift-crypto) and applies `linux.patch`, which drops `@objc` and `NSObject`
from `iTermAIError.swift` and `StableSessionID.swift`. That patch is the only
change to upstream source. A shim for any other Darwin-only API goes in
`harness/Sources/WireFixtures/Shims/`, one file per API, with a `// shim:`
comment naming what it stands in for.

On Linux in Docker:

```sh
docker run --rm -v "$PWD/fixtures/harness:/harness" -w /harness swift:6.2-noble \
    bash -c './sync-upstream.sh && swift build'
```

## Files

- `crypto-vectors.json` (generated by `wire-fixtures`): canonical encoding,
  pairing-code parsing, room names, SAS codes, relay-join signatures for both
  roles, and Noise prologues. All bytes are lowercase hex. In `pairingCodes`,
  `upstreamOk`, `upstreamError` and the parsed fields come from upstream
  `PairingCode.parse`; `androidAccepts`/`androidReason` are the Android app's
  policy, written in `main.swift`: only a `v=1` code with a relay origin is
  accepted (`resolverUnsupported` for `v=2`, `missingRelay` for a `v=1` code
  without `relay=`, otherwise the upstream error name). Join signatures are
  deterministic RFC 8032 Ed25519 only with swift-crypto's BoringSSL backend,
  so regenerate on Linux: Darwin CryptoKit randomises them.
  QR query values are percent-decoded without turning `+` into a space
  (upstream keeps a literal `+`), so Android parses the raw query with its own
  `&`/`=` splitter plus percent-decoding, never `Uri.getQueryParameter` or
  `URLDecoder`.
- `messages/session/*.json` (generated): session envelopes from v3.7.7, each
  `{"direction", "swiftValue", "json"}`. `json` is the envelope as upstream
  `WireCoding` encodes it, built the way the real flow builds it (iOS
  `CompanionClient`/`CompanionSession` for phoneToMac, Mac `CompanionLink`
  and `CompanionHostBridge` for macToPhone). Request IDs follow one relay
  connect: `relayRoomSecret` 1, `hello` 2, `ping` 3; replies copy the ID;
  `unpairing` and `unpaired` have none. `WireCoding.encode` writes keys in
  hash order, which changes from run to run, so `json` is the output of
  `WireCoding.makeEncoder()` with `.sortedKeys` added, embedded verbatim
  (no whitespace, `/` escaped as `\/`). Only the JSON tree is meaningful:
  compare trees, never bytes. `hello-phone` advertises upstream's revision
  15 as the reference; the app itself sends 11. `hello-mac*` are replies to
  a revision-15 phone; a phone below 14 gets no `macStatus`. `main.swift`
  decodes every sample (both upstream's bytes and the stored ones) with
  `WireCoding` and requires the same value back.
- `messages/confirmation/{accepted,rejected}.json` (generated): the exact
  UTF-8 text of `PairingConfirmation.encoded()`, a bare JSON frame with no
  envelope. Here bytes are fixed, so they are stored as a string.
- `messages/revision.json` (generated): `CompanionProtocolVersion.current`
  and `.minimumPeer` at v3.7.7, what the Mac speaks.
- `noise/xk-25519-chachapoly-blake2s.json`: the `Noise_XK_25519_ChaChaPoly_BLAKE2s`
  entry of cacophony's `vectors/cacophony.txt`, unchanged except for sorted
  keys, with the source commit in `source`. Not generated by the harness.
