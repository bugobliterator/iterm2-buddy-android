# Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the Pixel, the owner lists the Mac's iTerm2 sessions, watches one live as HEVC video, zooms, types into it, scrolls its history, selects and copies, and drives iTerm2 browser sessions.

**Architecture:** The session's receive loop splits decrypted frames: media (`0x01`) and stream-scoped control messages go, in order, to an app-scoped `StreamController` through a bounded suspending sink; everything else stays on the existing request/event paths. The controller owns the watch intent, link scoping, generations, acks and keyframe requests, and feeds a `VideoOutput` backed by an async MediaCodec HEVC decoder rendering to a TextureView surface under Compose zoom/pan. Sessions becomes the home screen; input goes through one ordered sender.

**Tech Stack:** Kotlin 2.4, Jetpack Compose (Material 3, `AndroidEmbeddedExternalSurface`, `PullToRefreshBox`), `androidx.lifecycle:lifecycle-process` (`ProcessLifecycleOwner`), MediaCodec / MediaCodecList, kotlinx-coroutines, kotlinx-serialization-json (tree API). Tests: JUnit 4, kotlinx-coroutines-test, the in-process fake relay and `FakeMac`, AndroidX test runner for the one instrumented decoder test. Fixtures: the Swift harness (Swift 6.2, `swift:6.2-noble` in Docker), ffmpeg with libx265 for the HEVC clip.

**Spec:** `docs/superpowers/specs/2026-11-16-sessions-design.md`, with byte-level facts in `docs/superpowers/specs/2026-11-16-sessions-protocol-notes.md` (cited as *notes* → section) and the pairing wire rules in `docs/superpowers/specs/2026-11-15-protocol-notes.md`.

**Scope:** Three sub-phases, in order, each ending with the owner's on-device check: **Live Session**, **History and Selection**, **Browser Sessions**. The lead asks the owner after each check before starting the next sub-phase. Agent Chat, Approvals, Notifications and the foreground service are out of scope.

**Review:** revised after the Codex Astra and Gemini 4 Argon adversarial reviews and two owner decisions (screen kept on in session views; Fit to phone never undone). Each finding's disposition is in *Review Dispositions* at the end.

## Global Constraints

- Package `dev.bugobliterator.itermbuddy`; `minSdk 34`; single module `app`; target Pixel 9, Android 15+. Paths below are under `app/src/main/java/dev/bugobliterator/itermbuddy/` (main) and `app/src/test/java/dev/bugobliterator/itermbuddy/` (test) unless written in full.
- Target iTerm2 **3.7.7**, upstream tag `v3.7.7` (`e0025340b49a2fc6415f490d77bbead5d3e0583e`).
- `ProtocolRevision.REVISION`: **13** from the Stream Messages task, **15** from the Browser Messages task. `MINIMUM_PEER` stays **11**. Browser input is used only when the Mac's hello revision is ≥ 15.
- Stream start params exactly `{"supportedCodecs":["hevc"],"maxFrameRate":30,"maxMediaFrameVersion":2}`; `maxBitrate` omitted. Never send `updateStreamParams`.
- Media frame (big-endian): version 1 header 22 bytes, version 2 header 34 bytes; fields `version u8, flags u8, streamID u32, sequence u32, ptsMilliseconds u64, [v2: generationId u32, liveTop i64], payloadLength u32`; reject other versions, short buffers and `payloadLength` ≠ remaining bytes. Flags: bit0 `keyframe`, bit1 `configChanged`, bit2 `endOfStream` (never set by the Mac).
- `codecExtradata` = `u16 count`, then per set `u32 length || bytes` (not hvcC). MediaCodec `video/hevc`, `csd-0` = each set prefixed `00 00 00 01`, concatenated. Access units: each 4-byte big-endian NAL length replaced by `00 00 00 01`.
- Mac flow control: before the first ack all frames flow; after it, non-keyframes stop when `lastSentPTS − lastAckedPTS > 500 ms` or reported `queueDepth > 4`. Insurance keyframe 0.3 s after the last P-frame. **Every media frame the controller dequeues is acked** (`streamAck{streamID, lastPTSMilliseconds: frame pts, queueDepth: 0}`), including frames it drops. **`queueDepth` is always 0**, exactly as iOS (`IOS/Screens/SessionView.swift:983`): a real depth can block the Mac with no later event to unblock it. Memory is bounded by byte budgets instead (next item).
- Byte budgets, never silent drops before the ack: relay transport queue 64 MiB (over it the connection is closed and reconnects; encrypted chunks are never dropped), stream inbox 256 items **and** 32 MiB of media bytes (the receive loop suspends at either), decoder pending input 16 MiB (over it, pending non-keyframes already acked are discarded and the decoder waits for a keyframe). All three are injectable.
- Stream IDs start at 1 per link (repeat across reconnects); stream state is keyed by link id. One stream at a time.
- `streamEnded` reasons: `stoppedByClient`, `sessionClosed`, `superseded`, `dataLimitReached`, `error` (defined, never sent). `unknownSession` on start is treated as `sessionClosed`. No auto-restart after `streamEnded`.
- Session tree fetch timeout 15 s; Mac pushes `sessionTree` with no requestID at most every 2 s (phone revision ≥ 13).
- `sendKey`: all four modifier booleans (`control`, `shift`, `leftOption`, `rightOption`) always present; `shift` always false; special raw values exactly `escape, tab, backspace, forwardDelete, up, down, left, right, home, end, pageUp, pageDown, insert, f1`…`f12` (25 values). Return is `text "\n"`; ^C is `text "c"` with `control:true`. Never invent a special key (the Mac drops the whole message).
- `resizeSession`: columns 60 (portrait) / 120 (landscape), Mac clamps to [1, 4096]; never sent automatically; disabled when `canResize == false` or for a browser.
- `resizeSession` is never undone: leaving the view does not restore the Mac window (owner decision, iOS parity). Fit is offered only when `canResize == true`; otherwise the view explains the Mac-side change.
- Screen kept on (owner decision) while a live or browser session view is showing, scoped to that screen; the session list and Settings let the phone lock.
- History tiles: 50-line slots at `firstAbsLine + 50·i`, each request's `lineCount = min(50, liveTop − slotFirstAbsLine)` (history only, never live rows); a slot fetched short is refetched when history grows; Mac caps a tile at 200 lines, ≤ 6 in flight, ≤ 24 queued, 20 s per-request deadline; cache cleared on a new generation or stream; byte budgets 32 MiB encoded PNGs, 96 MiB decoded bitmaps (displayed ones included).
- Selection: long press 0.3 s; `mode` read only on `begin`; columns are visual.
- Browser: `browserTap`/`browserScroll` coordinates in encoded-image pixels, origin top-left; scroll flushed at 20–30 Hz with integer deltas, fling decay `0.998^ms` until < 30 px/s; `browserLoad` text trimmed, skipped when empty.
- Relay: frames ≤ 256 KB, 500 frames/s/room; owner's relay `RELAY_DAILY_BYTE_QUOTA=8589934592`. Mac budget 400 MiB per stream per rolling 24 h.
- JSON numbers: a Kotlin `Double` that is integral and |x| < 2^53 is written as an integer literal (`30`, not `30.0`), as Swift's `JSONEncoder` writes it. Parity tests compare the JSON tree exactly.
- Every phone→Mac message has an upstream sample and a parity test; a mismatch is a failure, not a warning. Every new Mac→phone case has a sample and a decode test.
- No terminal content in logs: frames, typed or pasted text, selection text, URLs, page titles and session names are never logged. GUIDs, stream IDs, sizes and counts may be. Every type that carries such content overrides `toString()` to redact it (lengths only), and each has a test that its `toString()` contains none of a sentinel value: `Key.Text`, `KeyEvent`, `SendKey`, `PasteText`, `SessionSummary`, `PeerEntry`, `PaneEntry`, `TabEntry`, `WindowEntry`, `SessionTree`, `SessionRow`, `LiveViewState` (via `SessionSummary`), `SelectionText`, `BrowserLoad`, `BrowserNavigationState`, `BrowserNavigationChanged`, `AddressFieldState`.
- Tests: sandboxed (no fixed paths or ports), parallel (`maxParallelForks` = processors), virtual time; every timeout and interval in production code is injectable.
- Builds, SDK installs, JVM tests and fixture generation run in cloud sessions; instrumented tests and on-device checks run on the Mac with the Pixel over adb.
- Code is written by Opus 5.5 or better subagents, model passed explicitly. Commit author `bugobliterator <siddharthbharatpurohit@gmail.com>`; concise messages; no session links. pnpm, never npm.
- Names are descriptive: no numbered or lettered tasks, tests, fixtures, files or branches.

## Review Focus

- **Idle stream after a burst, with no feedback loop.** An agent prints a line and goes quiet; the last frame must be on screen within 250 ms, and a static screen must then go silent (no keyframe storm). No idle drain: low-latency config, immediate render, the Mac's insurance keyframe, as iOS. Pinned in *HEVC Decoder* (device `lastFrameOfBurstIsOutputWithoutMoreInput`) and the owner's idle and static-screen checks.
- **A frozen picture never shows as Live.** A decoder that accepts input and produces no output for 1 s is labelled "Picture stalled" with Retry; recovery is iOS's keyframe requests plus Retry, with no extra machinery; an idle terminal with everything output stays Live. Pinned in *Stream Controller* (`overdueOutputIsLabelledStalled`, `idleTerminalStaysLive`, `retryRestartsAnActiveStream`) and *HEVC Decoder* (`codecExceptionsReleaseAndRequestKeyframe`).
- **Acks never block the Mac.** Every dequeued frame is acked with `queueDepth 0`, including frames that cannot be decoded (no surface, rebuild, older generation, before the first config). Pinned in *Stream Controller* (`framesWithoutSurfaceAreStillAcked`, `ackQueueDepthIsAlwaysZero`, `streamKeepsFlowingPastFiveHundredMillis`).
- **Start correlation.** One start in flight at a time, bound to its link and request ID and adopted only while the same session is watched (iOS guard); any `streamStarted` not adopted is stopped. Pinned in *Stream Controller* (`lateStartReplyForOtherSessionIsStopped`, `reopeningSameSessionAdoptsInFlightStart`, `startAfterTimeoutIsStopped`, `switchingSessionsSerializesStarts`).
- **Lock, background, reconnect and rotation mid-stream.** No orphan stream on the Mac, dead-link frames ignored, the picture returns on its own, no start while backgrounded even across a reconnect, rotation neither stops nor restarts the stream. Pinned in *Stream Controller* (`backgroundStopsAndForegroundRestarts`, `reconnectWhileBackgroundedDoesNotStart`, `framesFromAnEndedLinkAreIgnored`), *Sessions Home* (`SessionNavigatorTest`) and the owner's rotation check.
- **Real IME sequences and stale input.** Gboard composing then Return, held backspace while composing, ^C with a held word, a multi-character commit with armed ctrl, an emoji: no doubled, lost or reordered characters; input queued for a previous link or session is discarded; a failed paste never sends its Return. Pinned in *Typing and Composer*.
- **A Mac window bigger than the decoder, and a browser config with 0×0 grid.** A resizable oversized window offers a Fit that fits; a full-screen one explains the Mac-side change; a browser config never divides by zero. Pinned in *Live View and Fit to Phone* (`fitGridCapsColumnsBeforeRows`, `tooLargeOffersFitOnlyWhenResizable`, `browserConfigHasNoFitAndNoCellMapping`) and *HEVC Decoder* (`oversizeConfigReportsTooLarge`).
- **Inbox deadlock and bounded memory.** A tile reply arriving while the inbox is full of media must not wedge the receive loop; a stalled consumer must not grow memory without bound. Pinned in *Media Channel* (`transportOverBudgetReconnects`), *Stream Controller* (`inboxSuspendsAtByteBudget`) and *History Tiles* (`historyTileReplyDuringMediaBurst`).
- **History tiles stay correct.** Partial tail tiles, selection changes and history clears invalidate the right tiles and supersede in-flight replies. Pinned in *History Tiles*.

Rules (design → Stream controller states):
- **Inbox.** `accept` puts inputs into a bounded inbox (`inboxItems` and `inboxMediaBytes`, whichever fills first) with a suspending send; it never drops. **Oversized item:** an item is always admitted when the inbox is empty, so one frame larger than `inboxMediaBytes` waits only for the inbox to drain and can never block forever; its size is bounded by `NoiseChannel.maxMessageBytes` (32 MiB), above which the link is closed before the frame exists. `LinkDown(messageTooLarge = true)` for the active stream's link ends the watch with `Ended(ERROR)` ("Stream ended" [RESTART]) instead of `Reconnecting`, so an oversized stream is not restarted in a loop. The consumer loop runs on a single-threaded dispatcher and never awaits a Mac reply. (Android-only: iOS has no inbox; the sink exists because Android's event flow is lossy.)
- **Watch state.** Three independent facts: the intent (`session`, `watchEpoch` bumped by every `open` and `close`, used to scope input), `foreground` (`pause()` → false, `resume()` → true), and the current link (`LinkUp`/`LinkDown`). A start is attempted only when all three allow it and no stream is active (iOS `startLiveStreamIfPossible`, `AppModel.swift:4586-4590`).
- **Start serialisation, as iOS (`AppModel.swift:4586-4628`).** At most one start in flight (`StartAttempt(linkId, guid, requestID)`); its `startSessionStream` runs in a child coroutine via `request(…, onLink = linkId, timeout = timeouts.start, onSent = { attempt.requestID = it })` and posts its outcome back to the inbox. Every other `StreamStarted` (late after a timeout, after `close()`/`pause()`, for another session, on an old link) gets `stopSessionStream(streamID, onLink = its linkId)` when that link is still current (iOS `AppModel.swift:4598-4603`; the request ID is the Android-only addition, needed because a reply can outlive its timed-out request here). When an attempt finishes without adoption, the current intent is started if its guid differs from the attempted one, or if the attempt was not a failure (it was superseded by close/reopen); a failed attempt for the same guid is not retried in a loop (iOS `AppModel.swift:4620-4627`).
- **Media** for the active `(linkId, streamID)`, as iOS `SessionView.swift:976-984`: parse, **ack first** (`AckSender.ack(pts)`, depth 0), then drop if the frame and config both have a `generationId` and the frame's is older (v1 frames, with null, are never dropped by generation), else `submit`. Media for any other link or stream: ignored, not acked.
- **Configs.** The config is stored in `activeStream` whatever `configure` returns, so `TooLarge` still has it for Fit. On the first config and on each generation change, `activeStream.liveTop` is set to `config.firstAbsLine + max(0, config.totalLines − config.rows)` (iOS `AppModel.swift:4403`); per-frame `liveTop` replaces it after that.
- **Lifecycle.** `pause()` sends `stopSessionStream` for the active stream, keeps the intent, state `Paused`. `LinkDown` clears the active stream (no stop on a dead link) and shows `Reconnecting` only when foreground, else stays `Paused`. `LinkUp` starts only when foreground. `resume()` starts when a link is up. `close()` stops and drops the intent. Every one of these, plus `streamEnded` and `retry()`, calls `video.reset()` (iOS `CompanionVideoView.reset`).
- **Ends and errors.** `streamEnded` for the active stream → `Ended(reason)` and the intent is dropped; `stoppedByClient` after our own stop is silent. Error reply `unknownSession` → `Ended(SESSION_CLOSED)`; other errors and timeouts → `Failed(StartFailed(retryable = true))`, retried on the next `LinkUp`/`resume` or `retry()`. `retry()` while a stream is active sends `stopSessionStream`, resets the video and starts a fresh stream.
- **Stalled label (Android-only, the design's anti-goal "a frozen picture that looks live").** iOS has no stall check; VideoToolbox outputs each frame or fails. MediaCodec can accept input and stay silent. So, with no recovery machinery: while `Live`, if `video.outputOverdueSinceMillis()` is older than `stallAfter`, the state is `Live(stalled = true)` (overlay "Picture stalled" [RETRY]); it clears only when no frame remains overdue (`outputOverdueSinceMillis()` null or younger than `stallAfter`). Decoder rules (design → Decode loop):
- Every codec operation and callback runs on one dedicated `HandlerThread`; `attachSurface`/`detachSurface` from the UI thread and `configure`/`reset` from the controller post to it (attach and detach wait for completion). `submit` offers into `PendingInputQueue` on the caller's thread; the decoder thread polls it when an input buffer is free.
- Format: `KEY_LOW_LATENCY = 1` when the decoder supports it, `KEY_PRIORITY = 0`, `KEY_MAX_INPUT_SIZE = max(width × height, 4 MiB)`, `csd-0` from `parameterSetsToCsd`. Each output `releaseOutputBuffer(index, true)` at once (as iOS `displayImmediately`).
- A decoder exists only with a surface and a config. The previous codec is released before a new one is configured on the same surface. Attaching a surface builds one and requests a keyframe. `submit` with no decoder, or before the decoder's first keyframe, returns false (iOS `enqueue` with no session, `CompanionVideoView.swift:104-112`).
- Any `RuntimeException` from a codec call (`CodecException`, `IllegalStateException`, `IllegalArgumentException`, `BufferOverflowException`) → release the codec, clear the pending queue, request a keyframe (iOS: a decode failure requests one, `CompanionVideoView.swift:129-145`); the next keyframe rebuilds it.
- `outputOverdueSinceMillis()`: a FIFO of accept times, one per frame accepted into the pending queue or codec (a refused frame adds none); each output pops the head (frames come out in order: the Mac's encoder has no reordering), so a partial output leaves the next frame's time at the head. When pending frames are dropped or replaced, or the codec is released, their entries are removed but the head keeps the earliest removed time, so replacement cannot reset the clock. `reset()` empties it.
- No idle drain. The last frame of a burst relies on low latency, immediate render and the Mac's insurance keyframe, as iOS does; the device test proves it. If it fails on the Pixel, the lead asks the owner before any drain is added.
